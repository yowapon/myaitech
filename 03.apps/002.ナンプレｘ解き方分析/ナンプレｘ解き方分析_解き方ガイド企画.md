# 教材企画: ナンプレ 解き方ガイド

アプリ 002 の付属ドキュメント。`03.apps/002.ナンプレｘ解き方分析/` の中に置き、扉ページと README の教材一覧には載せない（App Store 版へフォルダごと持ち出せるようにするため）。

## 0. 前提

- **対象読者** — このアプリでナンプレを解いていて、ヒントの文章の意味が分からずに止まった人。ナンプレのルール（1〜9を重複なく入れる）は知っている
- **想定レベル** — 入門。「候補」「メモ」という言葉を知らない前提から始める
- **所要時間** — 約20分。ただし通読を前提にしない。**ヒントから該当セクションへ直接飛んでくる読み方が主**
- **ゴール（読了後にできるようになること）**
  1. ヒントに出る10種類の手筋の名前を見て、盤面のどこを見ればよいか分かる
  2. 「マスが決まる手筋」と「候補が消えるだけの手筋」の違いが分かり、後者で数字を入れようとして混乱しなくなる
  3. 手が止まったとき、Lv1 から順に何を試すかの手順を自分で回せる

### なぜ作るか

現状のヒントは、手筋の名前と1〜2文の説明しか出さない。その説明文が「候補」「行・列・ブロックを見渡して」といった語を使っているため、**その語自体が分からない読者には何も伝わっていない**。言葉で盤面の空間関係を説明しようとしているのが原因なので、図で解決する。

### 出典を置かない方針

各手筋は手順・アイデアであって表現ではなく、著作権の対象にならない。文章はすべて書き下ろし、**図に使う盤面はアプリの生成エンジン（`EngineFactory`）で作ったものを使う**ので、外部から持ち込む素材がゼロになる。したがって出典セクションは設けず、末尾に「本ガイドの文章・図版はすべて本アプリのために書き下ろした」旨を1行置く。

副作用として `check_kyozai.py` の出典チェックが NG になる。`03.apps/` 配下はもともと同スクリプトの対象外（CLAUDE.md）なので問題にしない。

## 1. 図に使う盤面の作り方

`scripts`（scratchpad の `hunt.js`）で、アプリと同一の `EngineFactory` を Node に読み込み、9×9・Lv5 の問題をシード順に生成 → `humanSolve` で1手ずつ解かせ、**各手筋が実際に発火した最初の局面**を捕まえた。図はその局面の実データから機械的に SVG を起こす（手描きしない）。手描きすると図の中に論理矛盾が混ざり、それが一番読者を混乱させる。

| 手筋 | 出典局面 | 中身 |
|---|---|---|
| nakedSingle | seed 1 / 0手目 | r9c1 = 8 |
| hiddenSingle | seed 1 / 5手目 | r1c6 = 7 |
| pointing | seed 1 / 16手目 | 9 が r2c4・r2c6 に限定 → r2c8 から 9 を消す |
| claiming | seed 1 / 27手目 | 9 が r4c7・r5c7 に限定 → r5c9 から 9 を消す |
| nakedPair | seed 8 / 31手目 | r8c4・r8c9 が {1,9} → r8c8 から 1,9 を消す |
| hiddenPair | seed 14 / 13手目 | {1,9} が r7c2・r7c8 のみ → r7c2 から 7 を消す |
| nakedTriple | seed 24 / 16手目 | r1c8{1,6}・r3c8{6,7}・r8c8{1,7} → 同じ列の3マスから 6,7 を消す |
| hiddenTriple | seed 3 / 22手目 | {1,3,7} が r5c2・r5c5・r5c8 のみ |
| xWing | seed 8 / 30手目 | 6 が r6・r7 で c2・c4 のみ → r8c4・r9c4 から 6 を消す |
| xyWing | seed 1 / 28手目 | 軸 r5c5{4,8}・翼 r2c5{3,8}・r6c4{3,4} → r2c4・r3c4 から 3 を消す |

### 図の描き方（全図で共通）

**アプリの盤面とまったく同じ見た目にする。**CSS変数もアプリと同じ名前（`--cell-given` `--line-strong` `--cell-sel` `--accent`）を使う。読者が図とアプリの画面を頭の中でつなげられることが、この教材でいちばん効く。

- 9×9のマス目。確定している数字はすべて描く（読者が自分で検算できる）
- 候補の小さい数字は、**その手筋に関係するマスにだけ**描く。全マスに書くと読めない
- 色の役割は3つだけに固定する
  - **注目マス**（`--accent`の枠）… その手筋の主役
  - **効く範囲**（`--cell-peer`の塗り）… 行・列・ブロックの帯
  - **候補が消えるマス**（`--warn`の枠＋消える候補に取り消し線）
- 図の中に凡例を1行入れる

## 2. セクション構成

**セクションの `id` は、アプリのテクニックIDと同じ文字列にする。**ヒントのダイアログから `解き方ガイド.html#nakedSingle` の形で直接飛ばすため。

### s1. 全体像 — 難しさと手筋の対応

- **図解案** — 5段のはしご図。左に アプリのコース名（やさしい／ふつう／むずかしい／とてもむずかしい／おに）、右にその段で必要になる手筋。上の段は下の段を含む、という包含関係を線で示す
- **本文** — 難易度は「ひらめき」ではなく、必要な手筋の種類で決まっていること。上の段でも土台は Lv1・Lv2 であること
- 表を1つ（10手筋 × 段 × 別名）。別名（2国同盟、井桁など）を併記するのは、他所で調べたときに同じものだと分かるようにするため

### s2. 土台 — 「仲間」と「候補」

- **図解案A** — 1マスを選び、そのマスと同じ行・列・ブロックの20マスを塗る図。「このマスの仲間」
- **図解案B** — 1マスの候補が絞られていく4コマ。1〜9すべて → 行で消える → 列で消える → ブロックで消えて残り2つ
- **本文** — 候補＝「そのマスにまだ入れる数字」。ヒントの文章に出てくる「候補」はすべてこれ。アプリでは ✎メモ で自分で書ける
- **callout** — アプリの自動メモ設定に触れる

### s3. `id="nakedSingle"` Lv1 入る数字が1つ

- **図解案** — seed1 の実盤面。r9c1 を注目マスにし、仲間20マスを塗る。r9c1 の候補が 8 だけになっている様子
- **本文** — マスから見る。仲間に出ている数字を9個から引くと1つしか残らない
- 別名: 単独候補 / Naked Single

### s4. `id="hiddenSingle"` Lv2 置ける場所が1つ

- **図解案** — seed1 の実盤面。1行目の帯を塗り、7 が置けるマスを候補表示。r1c6 だけが残る
- **本文** — s3 と**見る向きが逆**であること。マスからではなく数字から見る。r1c6 自身には他の候補も残っているのに確定する、というのが要点
- 別名: 唯一の置き場所 / Hidden Single

**理解度チェック1** — 同じ盤面で、Lv1 と Lv2 のどちらの見方をしているかを選ばせる。誤答肢は「候補が1つだから」と「置ける場所が1つだから」を取り違えたもの

### s5. 分かれ道 — 数字が決まる手筋と、候補が消えるだけの手筋

- **図解案** — 2列の対比図。左「マスが決まる」（Lv1・Lv2）→ 数字を書き込める。右「候補が消える」（Lv3以上）→ 盤面の見た目は変わらない。右の下に「消したあとで Lv1・Lv2 に戻る」の矢印を回す
- **本文** — **ここがヒントが分かりにくい最大の理由**。Lv3以上のヒントは「候補をけずれます」としか言わず、数字が入らない。消したあとにもう一度 Lv1・Lv2 を探すと埋まる、という往復構造を明示する
- **callout warn** — メモを書いていないと、Lv3以上の手筋は使えない（消す対象が画面に無いため）

### s6. `id="pointing"` Lv3 ブロックで絞る

- **図解案** — seed1 の実盤面。2つ目のブロックを枠で囲み、9 の候補が2行目に一直線に並ぶ様子。矢印がブロック→行の外側へ伸び、r2c8 の 9 に取り消し線
- **本文** — ブロックの中で数字が1行に閉じ込められている → その行の他ブロックからは消せる。ブロックが行に効く向き
- 別名: Pointing Pair / Locked Candidates

### s7. `id="claiming"` Lv3 行・列で絞る

- **図解案** — seed1 の実盤面。7列目を帯で塗り、9 の候補が r4c7・r5c7（同じブロック内）に限定。矢印が行→ブロックの内側へ。r5c9 の 9 に取り消し線
- **本文** — s6 と**向きだけが逆**。列が示す先が1つのブロックに収まるなら、そのブロックの残りから消せる
- 別名: Claiming / Box-Line Reduction

**理解度チェック2** — pointing と claiming の向きを問う。誤答肢は向きを逆にしたもの

### s8. `id="nakedPair"` Lv4 裸のペア・トリプル（`id="nakedTriple"` は h3 に付ける）

- **図解案** — seed8 の実盤面。r8c4・r8c9 が {1,9} で、同じ行の r8c8 から 1,9 が消える。**「2マスに2つの数字を予約した」**という比喩を図中に置く（席が2つ、客が2人）
- **本文** — 2マスがどちらも {1,9} だけを持つなら、1と9はこの2マスで使い切る。順番は分からなくても占有は確定する
- **h3 トリプル** — seed24 の実盤面。3マスの候補が全部同じである必要はない（{1,6}{6,7}{1,7} でよい）ことが初心者の落とし穴なので、ここは図で明示
- 別名: 2国同盟 / 3国同盟 / Naked Pair・Triple

### s9. `id="hiddenPair"` Lv4 隠れたペア・トリプル（`id="hiddenTriple"` は h3）

- **図解案** — seed14 の実盤面。7行目で、1と9が置けるのは r7c2・r7c8 だけ。r7c2 に残っていた 7 に取り消し線
- **本文** — s8 と**入口が逆**。マスの候補ではなく、数字の置き場所を数える。消えるのは「他のマス」ではなく「そのマス自身の余分な候補」
- **h3 トリプル** — seed3 の実盤面
- 別名: 隠れ2国同盟 / Hidden Pair

**理解度チェック3** — 裸と隠れの違い（どちらから数えるか／どこが消えるか）

### s10. `id="xWing"` Lv5 X-Wing

- **図解案** — seed8 の実盤面。6 の候補位置を r6・r7 に絞り、c2・c4 の4点を線で結んで長方形を描く。c4 の下方向（r8c4・r9c4）に取り消し線
- **本文** — 2つの行で同じ2列にしか入らない → その2列は上下どちらかの組み合わせで必ず使われる → 同じ列の他の行からは消せる。「どちらの対角線に決まるかは分からないが、列を使い切ることだけは確定する」が核
- 別名: 井桁理論 / X-Wing

### s11. `id="xyWing"` Lv5 XY-Wing

- **図解案** — seed1 の実盤面。軸 r5c5{4,8} から翼2枚へ線を引き、共通して見えるマス（r2c4・r3c4）を網掛け。軸が4のとき／8のときの2通りを小さく2コマで併記し、**どちらでも3が現れる**ことを見せる
- **本文** — 場合分けが1回だけ入る唯一の手筋。総当たりではなく「2通りしかなく、どちらでも同じ結論」だから論理として成立する
- 別名: XY-Wing / Y-Wing

**理解度チェック4** — X-Wing が成立する条件（「同じ2列」であること）を問う

### s12. 手が止まったときの順番

- **図解案** — フローチャート。メモを書いたか → Lv1 → Lv2 →（埋まらなければ）Lv3 → Lv4 → Lv5 →（候補を消したら）Lv1 へ戻る、というループを明示
- **本文** — 上の段の手筋を先に探すのは効率が悪い。必ず下から。ヒントも同じ順で探していること
- **callout tip** — アプリの「解き方分析」で、自分がどの手筋で止まりやすいかが分かる

### まとめ

カード3枚（候補が土台 / Lv3以上は候補を消すだけ / 消したら下の段に戻る）＋ 書き下ろしである旨の1行。

## 4. 制約の確認

- 外部依存ゼロ（CDN・外部フォント・外部画像なし）
- 図はすべてインラインSVG。色は CSS 変数のみ
- ライト／ダーク切替。アプリと同じ `data-theme` 方式に合わせる
- 「数独」の語は使わない（ニコリの登録商標。要件定義 15〜20行目と同じ方針）
