# 教材企画: AIと作る自作ゲームをSteamで売るまでの全ルート

## 0. 前提

- **対象読者**: 高校生（プログラミングは授業や独学で少し触った程度。ゲーム開発・商売の経験はゼロ）
- **想定レベル**: 入門。専門用語は初出時に必ず言い換える
- **所要時間**: 約25分
- **開発の前提**: コードは Codex / Claude Code などのAIコーディングエージェントに書かせる。人間は「何を作るか」と「面白いか」の判断に集中する
- **この教材のゴール（読了後にできるようになること）**
  1. Steamでゲームを売るまでの手続き・費用・期限を、順番と数字で説明できる
  2. 「作る」より「知られる」が難しい理由を理解し、ウィッシュリストを軸にPR計画を立てられる
  3. Steamの公式イベントカレンダーから逆算して、自分の発売日と6か月スケジュールを引ける

- **意図的に外したこと**: ゲームエンジンの選び方の詳細、プログラミングの書き方、法人設立の手続き。「Steamで売る」流れに集中する

---

## 1. 全体像 — 「作る」は5工程のうちの1つでしかない

- 図解案: **プロセスフロー（5ステップ横並び）**。①企画 ②開発 ③Steam登録・審査 ④宣伝（ウィッシュリスト集め） ⑤発売・運営。②の下に「AIが強い」、④の下に「ここで差がつく」の注記を入れる
- 伝えること: 初心者は②だけを開発だと思っているが、実際は③の事務と④の宣伝に時間の半分が消える。AIで②が速くなったぶん、相対的に③④の比重が上がった
- 本文で補う内容: AIで作れる時代＝競争相手も増えた時代。差がつくのは工程④

## 2. 必要なもの — お金・アカウント・大人

- 図解案: **分解ツリー**。「Steamで売るのに要るもの」→ ①お金（$100/作品） ②アカウント類（Steamアカウント／Steamworks登録／銀行口座／税務情報） ③大人の名義（契約なので未成年は保護者が必要）
- 本文で補う内容:
  - Steam Direct料金は1作品につき100米ドル。返金はされないが、調整後の総収益が$1,000に達した後の支払いで回収できる
  - 登録には銀行情報・税務情報・身元確認が必須。ここが高校生の実質的な最初の壁
  - 契約行為なので、18歳未満なら保護者に名義と口座を用意してもらう相談が最初のタスク
- クイズ: なし

## 3. AIで開発する — Codex / Claude Code の役割分担

- 図解案: **2×2マトリクス**（縦軸: 正解が1つに決まるか / 横軸: 量が多いか）。「AIに丸投げしてよい領域（実装・バグ修正・リファクタ）」「人間が決める領域（面白さ・世界観・難易度）」を配置
- 本文で補う内容: AIは「仕様が言葉になっているもの」を高速に形にする。逆に「遊んで面白いか」は言葉にならないので人間が判断する。だからAI前提の開発では、毎日プレイして直す往復（プレイテスト）が最大の仕事になる
- callout: 生成されたコードの中身が分からないまま進めると、後で直せなくなる。1日1回は「このコードが何をしているか説明して」と聞く習慣

## 4. Steamworks登録からストア公開までの事務フロー

- 図解案: **プロセスフロー（縦または横6ステップ）**。Steamworks登録 → 身元/銀行/税務の確認 → $100支払い＆アプリ作成 → ストアページ作成 → Valve審査 → 「近日登場」公開
- 本文で補う内容: ストアページはValveの審査を通す必要がある。文章・画像・タグの不備で差し戻されることがあり、往復に日数がかかる前提で組む
- callout(warn): **ストアページは発売の最低2週間前に公開されている必要がある**。＝「明日出す」はできない

## 5. AI生成コンテンツの開示ルール（2026年版）

- 図解案: **Before/After 対比**、または左右2カラムの「申告が要る／要らない」表図。左＝申告不要（コード補助・デバッグ支援などの開発効率化ツール）、右＝申告必要（プレイヤーが体験するアート・音・物語・ローカライズ）
- 本文で補う内容: 2026年1月にValveが線引きを明確化。判断基準は「最終製品に含まれ、プレイヤーが体験するか」。Codex/Claude Codeでコードを書くだけなら申告不要だが、AI生成の画像やBGMを入れるなら申告が必要。開示内容はストアページに表示される
- callout(warn): 未申告はページ削除の対象になり得る。迷ったら申告する側に倒す

## 6. お金の流れ — 1,000円のゲームが売れると手元にいくら残るか

- 図解案: **比率バー**（Valve 30% / 開発者 70%）＋ その下に「$1,000万超で25%、$5,000万超で20%（超過分のみ）」の階段注記
- 本文で補う内容: 定価の30%がValveの取り分。残り70%からさらに$100の回収、税金、（使ったなら）素材購入費が引かれる。分配率が改善するのは累計$1,000万を超えてからなので、個人開発では実質70%固定と考えてよい
- クイズ: なし

## 【クイズ2】 AI開示ルールの線引き

## 7. ウィッシュリストが生命線

- 図解案: **バーチャート**。ウィッシュリスト数（5,000 / 10,000 / 30,000）と、発売1週目の推定販売本数（500〜750 / 1,000〜2,500 / 3,000〜4,500）を並べる。出典明記
- 本文で補う内容: ウィッシュリスト＝「発売したら教えて」の予約リスト。発売時にSteamがまとめて通知を出すので、初動売上に直結する。目安は発売日までに7,000〜10,000。転換率は発売週で10〜25%程度だが、ばらつきは非常に大きく単独では予測にならない
- callout(tip): 数字より大事なのは「ストアページを早く公開して、集める期間を長く取る」こと

## 8. PRの手段 — 高校生でも今日から打てる手

- 図解案: **階層スタック**（下から上へ、コストが低い順）。①SNS（X/TikTok/YouTube Shorts でGIF投稿） ②Discordコミュニティ ③配信者へのDM・キー配布 ④ゲームメディアへのプレスリリース ⑤イベント出展
- 本文で補う内容: 全部やる必要はない。動くGIFを毎週1本出すのが最も費用対効果が高い。配信者へのDMは長文NG、ゲーム名・ジャンル・魅力・ストアURLを簡潔に
- callout: 宣伝は「発売直前に始める」のでは遅い。開発中の進捗そのものがコンテンツになる

## 9. 公開タイミング — Steamのイベントカレンダーから逆算する

- 図解案: **タイムライン**。2026年10月オータムセール→Nextフェス（10/19-26）→絶叫フェス→ウィンターセール（12/17-1/4）→2027年2月Nextフェス→3月スプリングセール。Nextフェスの登録期限（開催の約7週間前）を吹き出しで注記
- 本文で補う内容:
  - **Steam Nextフェスは1作品につき1回だけ**。発売前・デモ公開が条件で、フェス終了後にリリースする必要がある。使いどころを間違えると取り返せない
  - ジャンル別フェス（料理フェス、絶叫フェス等）は該当すれば無料で露出が取れる
  - 大型セール期間の発売は、値引き競争に埋もれるので新作には不利になりやすい
- クイズあり

## 【クイズ3】 Nextフェスの使い方

## 10. サンプルスケジュール（6か月・小規模作品）

- 図解案: **タイムライン（月単位6区切り）**。M1企画/プロトタイプ、M2-3開発、M4ストアページ公開＋PR開始、M5デモ完成＋Nextフェス、M6修正→発売
- 本文で補う内容: 逆算の起点は発売日ではなく「Nextフェスの登録期限」。そこから遡って、ストアページ公開はさらに前。事務手続き（$100支払い、身元確認）は最初の月に済ませておく
- 表: 月 / やること / この時点の期限

## 11. よくある失敗と対策

- 図解案: **Before/After 対比**、または3カード＋アイコン。「レビュー10件未満で埋もれる」「日本語のみで市場が10分の1」「発売2週間前は発売日を変更できない」
- 本文で補う内容: レビュー件数が10件に満たないとSteamの推薦機能（ディスカバリーキュー）に載りにくく、露出が止まる。英語対応の有無で母数が桁で変わる。発売直前のスケジュール変更は効かないので、余裕を持った日付を最初に置く
