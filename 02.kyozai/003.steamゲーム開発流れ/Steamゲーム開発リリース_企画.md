# 教材企画: AIと作る自作ゲームをSteamで売るまでの全ルート

## 0. 前提

- **対象読者**: 前提知識ゼロの入門者（説明は高校生レベルの語彙で書く）。ただし**実際に手続きを行うのは成人**（個人事業主または法人）であることを前提にする
- **想定レベル**: 入門
- **所要時間**: 約35分
- **開発の前提**: コードは Codex / Claude Code などのAIコーディングエージェントに書かせる。人間は「何を作るか」と「面白いか」の判断に集中する
- **この教材のゴール（読了後にできるようになること）**
  1. Steamで売るまでの手続き・費用・税務・期限を、順番と数字で説明できる
  2. テスト（Playtest／デモ／早期アクセス）と価格・割引のルールを踏まえて発売計画を立てられる
  3. Steamの公式イベント日程から逆算して、発売日と6か月スケジュールを引ける

- **意図的に外したこと**: ゲームエンジンの選び方の詳細、プログラミングの書き方、法人設立の具体手続き

### 改訂メモ（第2版）
- 「18歳未満は保護者の名義」という記述を撤去。**Steamworksは事業としての契約**であり、本人確認・銀行口座・税務情報が要る、という事実ベースの説明に置き換えた
- ベータテスト（Steam Playtest）、価格設定、割引ルール、発売後の運営の4セクションを新設
- 既存セクションは構成を変えず、観点を1〜2個ずつ肉付け

## 1. 全体像 — 「作る」は5工程のうちの1つ

- 図解案: **プロセスフロー（5ステップ）**。①企画 ②開発 ③登録・審査 ④宣伝 ⑤発売・運営
- 肉付け: この5工程は並列ではなく、③の周辺に「テスト」「価格設定」「開示申告」など締切付きの作業がぶら下がっていることを予告する

## 2. 必要なもの — 費用・本人確認・税務

- 図解案: **分解ツリー**。①費用（$100/作品） ②本人確認（銀行口座・事業者情報） ③税務（W-8BEN／マイナンバー）
- 本文で補う内容:
  - Steam Direct料金は1作品100米ドル、返金不可だが調整後の総収益$1,000到達後の支払いで回収
  - 登録には銀行口座・本人確認・税務情報が必須
  - W-8BENで日米租税条約の適用を受ければ米国源泉徴収は0%。日本の個人はマイナンバーが納税者番号として使え、EIN取得は不要
- callout: 事業としての契約なので、日本側の開業届・確定申告が後からついてくる

## 3. AIとの役割分担

- 図解案: **2×2マトリクス**（言葉にできるか × 作業量）
- 肉付け: 素材の権利関係（ライセンス一覧）はAIが面倒を見てくれない領域として追加

## 4. Steamworks登録からストア公開まで

- 図解案: **縦6ステップのフロー**
- 肉付け: 審査ではストアページだけでなく実ビルドも確認される。起動しない／クラッシュ／言語設定の食い違いが差し戻しの定番
- callout(warn): ストアページは発売の最低2週間前から公開

## 【クイズ1】 2週間ルール

## 5. テストの4段階 — Playtest / デモ / 早期アクセス / 正式版 ★新設

- 図解案: **完成度を横軸にした4ボックス比較**。各ボックスに「公開範囲」「無料/有料」「注意点」
- 本文で補う内容:
  - Steam Playtest はキー配布なしで非公開テストができる機能。別appIDで動くのでウィッシュリスト・プレイ時間・レビューに影響しない＝壊れた状態を見せても安全
  - デモは「見せる」ためのもので、Nextフェス参加の条件
  - 早期アクセスは未完成のまま有料販売する形式。正式版の評価を先に消費し、更新が止まると警告表示の対象
  - 最初の1本なら Playtest + デモ の2段で十分
- callout(key): テストで一番よく壊れているのは「最初の5分で何をすればいいか分かるか」

## 6. AI利用の開示ルール（2026年版）

- 図解案: **申告不要／必要の左右対比**
- 肉付け: 「事前生成」と「実行時生成」で申告が分かれること、後者は不適切出力の防止策の説明も要ること

## 【クイズ2】 AI開示の線引き

## 7. お金の流れ — 70/30

- 図解案: **比率バー**＋ティア注記
- 肉付け: 入金は月次でまとめて。返金分は差し引かれるので、発売直後の売上数字がそのまま手元には来ない

## 8. 価格をいくらにするか ★新設

- 図解案: **バーチャート**。基準価格 $15.99 に対する日本円推奨額 — 為替換算2,500円 / 多変数換算2,050円 / 購買力換算1,600円（出典: Steamworks価格換算探索ツールの解説記事）
- 本文で補う内容: 37通貨・4地域グループ。換算方式は3つで、Valveは多変数換算を標準に据えている。価格の引き下げは自由だが、**引き上げると30日間割引できなくなる**

## 9. 割引とセールのルール ★新設

- 図解案: **タイムライン**。発売前＝ローンチ割引の設定枠 → 発売日 → ローンチ割引7〜14日（10〜40%）→ 発売後30日は割引不可 → 以降は割引可（前回割引から30日空ける）／季節セールはクールダウン免除
- 本文で補う内容: ローンチ割引は発売日より前にしか設定できず、後から追加できない。発売直後に売れ行きが鈍っても値下げで立て直す手はしばらく使えない＝価格と割引は発売前に決め切る項目

## 【クイズ3】 ローンチ割引の設定タイミング

## 10. ウィッシュリストが生命線

- 図解案: **バーチャート**（WL 5,000 / 10,000 / 30,000 と1週目販売見込み）
- 肉付け: ウィッシュリストは削除もされる。総数より「月ごとの増え方が止まっていないか」を見る

## 11. PRの手段

- 図解案: **階層スタック5段**（コスト低い順）
- 肉付け: どの投稿でウィッシュリストが伸びたかを月単位で記録する

## 12. 公開タイミング — 公式イベントから逆算

- 図解案: **タイムライン**（2026/10〜2027/3の実日程、Nextフェス強調）
- 肉付け: 曜日の話（金曜発売は不具合対応が土日にずれる。個人なら火〜木）

## 【クイズ4】 Nextフェスの使い方

## 13. サンプルスケジュール（6か月）

- 図解案: **ガントチャート6行**。企画・試作／登録と税務／開発の往復／Playtest／ストア公開・PR／デモ・Nextフェス・発売
- 肉付け: Playtest を3〜4か月目に挟み、そこで出た問題を直してからデモを作る

## 14. 発売後の運営 ★新設

- 図解案: **ループ図**。①レビュー・返金理由を読む → ②修正 → ③アップデート告知 → ④再流入 → ①
- 本文で補う内容: 返金は「購入から2週間以内かつプレイ2時間未満」なら理由を問わず通る＝最初の2時間の体験が返金率に出る。返金コメントと低評価は管理画面から読める。更新告知そのものが再流入になる

## 15. よくある失敗と対策

- 図解案: **失敗→対策の3行対比**
- 肉付け: 発売2週間前を切ると日付を動かせない／レビュー10件／言語対応
