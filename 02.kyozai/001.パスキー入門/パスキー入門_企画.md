# 教材企画: パスキー入門 — 「別のPCからログインしたいのにパスキー登録しろ」と言われる理由

## 0. 前提

- **対象読者**: 中学生〜高校生（およびネット証券のログインでつまずいた保護者）
- **想定レベル**: 入門。暗号やITの前提知識ゼロ
- **所要時間**: 約15分
- **切り口**: 抽象的な「パスキーとは」だけで終わらせず、**「iPhoneではパスキーでログインできるのに、別のPCからログインしようとすると新しくパスキーを登録しろと言われる」という実際のつまずき**を最終目的地にする
- **ゴール（読了後にできるようになること）**
  1. パスキーの正体（秘密鍵と公開鍵のペア）を、鍵と鍵穴のたとえで説明できる
  2. Windows Hello / Windows PIN / iCloudキーチェーン が、パスキーのどの部分の話なのかを区別できる
  3. 別のPCからログインしたいときの2つの解決策（QRコードで借りる／PCにも登録する）を選べる

## 用語の交通整理（この教材の背骨）

読者の混乱の正体は「4つの言葉が同じ階層の言葉だと思っていること」。実際には階層が違う。

| 言葉 | 正体 | 階層 |
|---|---|---|
| パスキー | 秘密鍵＋公開鍵のペアそのもの | **中身** |
| iCloudキーチェーン | パスキーをしまう金庫（Apple製） | **保管庫** |
| Windows Hello | パスキーをしまう金庫（Microsoft製）＋本人確認の仕組み | **保管庫** |
| Windows PIN | Windows Helloの金庫を開ける暗証番号 | **開け方** |

この「中身 / 保管庫 / 開け方」の3層を最初に立てて、以降のセクションを全部そこに紐づける。

---

## 1. パスワードの何が問題だったのか

- 図解案: **バーチャート（量）**。国内フィッシング報告件数の推移。2025年12月単月で190,500件という具体値を出し、「パスワードは盗める」を数字で殴る
- 伝えること: パスワードは「知っていれば誰でも使える合言葉」なので、盗まれた瞬間に本人と偽者の区別がつかない
- 本文: 200〜300字。使い回し・フィッシングの2点だけ

## 2. パスキーの正体は「2つでセットの鍵」

- 図解案: **分解ツリー**。パスキー → 秘密鍵（自分の端末に残る）／公開鍵（サービスに預ける）。南京錠と鍵のたとえを図の中に入れる
- 伝えること: 公開鍵は盗まれても無害（鍵穴だけ盗んでも開かない）、秘密鍵は端末から一度も外に出ない
- 本文: 「だからサービス側が情報漏洩しても、パスワードのようには使われない」

## 3. ログインするとき何が起きているか

- 図解案: **プロセスフロー（4ステップ）**。①サイトが「お題」を送る → ②端末が本人確認（顔・指紋・PIN） → ③秘密鍵でお題に署名 → ④サイトが公開鍵で検証
- 伝えること: 通信に流れるのは「署名」だけで、鍵そのものは流れない。だから偽サイトに入力してしまう事故が原理的に起きない
- 本文: フィッシング耐性の理由をここで1行

## 4. 秘密鍵はどこにしまわれる？ — 「パスキー保管庫」は世界ごとに別々

- 図解案: **階層スタック（3層）**。上から「サービス（野村證券）」「パスキー保管庫（Windows Hello / iCloudキーチェーン / Googleパスワードマネージャー）」「本人確認（顔・指紋・PIN）」
- 伝えること: ここが教材の分水嶺。保管庫は3つの勢力に分かれていて、**勢力をまたぐ同期はしない**
- クイズ1: パスキーの「秘密鍵」はどこにあるか

## 5. Windows Hello と Windows PIN

- 図解案: **Before/After 対比**。「パスワード＝どのPCからでも使える／ネットを流れる」 vs 「PIN＝そのPCの中だけ／ネットを流れない・TPMが守る」
- 伝えること: PINが4桁でも安全なのは、そのPC1台の中でしか意味を持たない数字だから。PINは「パスキーの代わり」ではなく「金庫の開け方」
- 本文: TPMとハンマリング防止（試行回数制限）を1行ずつ

## 6. iCloudキーチェーン

- 図解案: **構造図**。同じApple IDで結ばれたiPhone / iPad / Mac の3台が同期線でつながり、その輪の外にWindows PCが点線で置かれている
- 伝えること: Apple同士なら自動で増える。だが輪の外のWindowsには届かない ＝ ユーザーの困りごとの直接の原因
- クイズ2: iPhoneで登録したパスキーがWindows PCに出てこない理由

## 7. 【本題】なぜ別のPCで「パスキーを登録しろ」と言われるのか

- 図解案: **2×2マトリクス**（縦軸＝端末、横軸＝保管庫）。iPhoneのパスキーはAppleの箱の中にあり、Windows PCのHelloの箱は空、という状態を一目で見せる
- 伝えること: サービスは端末を疑っているのではなく、**そのPCの保管庫に鍵が1本も無い**だけ。「登録しろ」は「このPCにも合鍵を作れ」という意味
- 本文: ここが教材のクライマックス。300字使ってよい

## 8. 解決策A: QRコードでiPhoneのパスキーを借りる（クロスデバイス認証）

- 図解案: **プロセスフロー**。PCにQR表示 → iPhoneで読む → Bluetoothで「近くにいる」確認 → iPhoneで顔認証 → PCのログイン成立
- 伝えること: Bluetoothはデータの通り道ではなく**近さの証明**に使われる（遠隔からの乗っ取りを防ぐため）。QRは1回限り
- 本文: PC側に何も残らないので、他人のPC・共用PCではこちらが正解
- クイズ3: Bluetoothの役割は何か

## 9. 解決策B: そのPCにもパスキーを追加登録する

- 図解案: **構造図**。1つの口座に複数のパスキーがぶら下がる（野村證券は1口座5件まで）。iPhone／自宅PC／予備、と枠が埋まっていく絵
- 伝えること: パスキーは1つに絞る必要がない。自分専用のPCなら登録したほうが毎回速い。追加登録には既存の方法での本人確認が要る
- 本文: 野村證券の場合の具体例（Windows Hello / Googleパスワードマネージャー / iCloudキーチェーン / セキュリティキーから選ぶ）

## 10. どちらを選ぶ？ ＋ つまずきポイント

- 図解案: **2×2マトリクス**（縦＝そのPCを今後も使うか、横＝自分専用か）。4象限に「登録する／QRで済ませる」を配置
- 伝えること: 判断基準は「そのPCが自分のものか」だけ
- 本文: 注意点をcalloutで2つ（機種変更前に予備を作る／偽サイトのQRは原理的に成立しないが、QRを名乗る別の詐欺には注意）
- クイズ4: 共用PCで1回だけログインしたいときの正解

## まとめ

- カード3枚: 「パスキー＝端末から出ない秘密鍵」「Hello / キーチェーンは金庫、PINは開け方」「登録しろ＝このPCに合鍵を作れ」
