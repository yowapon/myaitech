Macを持たないWindowsユーザーが、App Storeにアプリを出すまで

iOSアプリにMacが要るのは事実ですが、要るのは全工程のうち4つだけです。どこで止まるのか、どんなMacをどう調達するのか、そして発売前に決めておくべき特許の判断までを、数字と日付で整理します。

対象: Mac未経験のWindowsユーザー レベル: 入門 所要 約45分 更新: 2026-08-11

この教材について

🎯

読み終えるとできるようになること

  1. Windowsで完結する範囲とmacOSが要る範囲を工程単位で線引きし、必要なMacの性能を作るアプリから逆算できる
  2. Macの調達方法4つを費用と手間で比較し、自分の本数に合う方法を選べる
  3. 登録・税務・審査・SDK期限に加えて、特許を「とる／とらない」の判断を発売日より前に下せる

主な参照元: Apple Developer Program 登録 / SDK minimum requirements / 特許庁 新規性喪失の例外（全出典は末尾）

1. 工程を「どのOSでやるか」で3レーンに分ける

「iOSアプリを作るにはMacが要る」は正しい命題ですが、「Macで全部やる」は誤りです。実際にmacOSでしかできないのは、真ん中のレーンに並ぶ署名・アーカイブ・アップロードの区間だけです。

この図がこの教材全体の地図になります。以降の章は、上のレーンを厚くして真ん中のレーンを薄くするための話だと考えてください。

2. Windowsだけで完結できるのか

結論を先に言います。「アプリを作る」だけならWindowsで完結します。「App Storeに出す」なら完結しません。

ただし止まるのは4工程だけで、しかもそれは連続した1本の作業です。登録も税務情報の提出もメタデータの入力も審査のやり取りも、すべてブラウザで済みます。Macが必要なのは「ビルドを作って送る」瞬間だけです。

🔑

問いを立て直します。「Macを買うか」ではなく「Xcodeを1時間だけどこで動かすか」。こう置き換えると、選択肢は4つに増えます。

3. なぜその4工程だけがmacOSなのか

Xcodeは macOS 専用で、Windows版もLinux版もありません。そしてiOSアプリは署名されていないと実機でもストアでも動かず、署名を行う codesign も提出形式を作る xcodebuild も Xcode 同梱です。

つまり「Macが要る」の正体はXcodeのツールチェーンが要るということです。Flutter公式のセットアップ手順にも、iOSビルドには macOS と Xcode が必要だと明記されています。ここを外す抜け道はありません。

4. やってはいけない回避策

macOSのソフトウェア使用許諾契約（SLA）は、インストール先を Apple-branded computer に限定しています。仮想化が認められるのは「すでに macOS が動いている Apple 製ハードウェア上」で追加2インスタンスまでという条件付きで、PC上のVMやHackintoshはこの例外に入りません。

⚠️

手順を解説した記事は検索すれば出てきますが、契約違反であることは変わりません。Apple Developer Program という契約を並行して結ぶ立場では、リスクの取り方として釣り合いません。

理解度チェック 1

macOSのライセンス上、認められているのはどれですか。

SLAが限定しているのは「ハードウェアがApple製かどうか」です。BのようにApple製ハードウェア上でなら仮想化は認められており、追加2インスタンスまで使えます。AはPCが非Apple製なので違反。Cは「個人・非商用なら何でもよい」という条件は存在しないため誤りで、用途が限定されるのはApple製ハードウェア上での仮想化の場合の話です。

5. Macの調達方法4つ

年に1〜2本なら時間課金が圧倒的に安く済みます。実例として、Unity製のパズルゲームを個人リリースした開発者はクラウドMacの利用約15時間で完了しています。逆に週次でビルドを回すなら、実機かCIに寄せたほうが総額もストレスも下がります。

⚠️

Mac mini の最小構成は2026年6月24日の価格改定で 94,800円から134,800円 になりました。「とりあえずMacを買う」の判断コストが上がっているのが2026年の前提です。

6. どれだけの性能が要るか — 作るアプリのパターン別

全パターンに共通する下限は「Xcode 26 が動くこと」です。Xcode 26 は macOS Sequoia 15.6 以降、26.4 以降は macOS Tahoe 26.2 以降を要求します。

メモリの基準線が16GBに上がった根拠は Apple 自身が示しています。Xcode 16 の予測コード補完の動作要件に「Apple Silicon＋16GB以上の統合メモリ」を指定し、8GBでは足りない領域があることを公式に認めた形です。ストレージはXcode本体だけで約20GB、これにDerivedDataとシミュレータが積み上がるので、256GBは数か月で枯渇します。

🔑

悩む前にまず「自分はパターンAでいけないか」を検討してください。Aで済むなら、この性能表を読む必要そのものがなくなります。

7. 何で作るか — Windowsで書けるフレームワーク

最終ビルドに macOS が要る点はどれも同じで、違うのはその手前をWindowsでどこまで進められるかです。クロスプラットフォーム系はWindows上で書いてAndroid実機やエミュレータで動作確認まで進められるため、前章のパターンAに収まります。

一方でネイティブSwiftを選ぶと書く段階から macOS が必要になり、パターンB以上に上がってクラウドMacの接続時間がそのまま膨らみます。Mac未経験者の1本目には向きません。

🔑

選ぶ基準は「どの言語が好きか」より「macOSに触る時間を何分に抑えられるか」です。

8. Apple Developer Program — 個人と組織の分かれ道

年会費は99米ドル（現地通貨の同等額）です。日本円の請求額は為替で動くので、公式表記の米ドルを基準に考えます。

組織登録はD-U-N-S番号の取得とWebサイトの用意で数日から数週間かかります。発売日から逆算して最初に着手する項目だと考えてください。

⚠️

個人登録すると、App Storeの販売者名として本名が公開されます。ペンネームで出したいなら法人化が必要という構造で、後から変更が効きません。登録前に決めてください。

9. お金を受け取る準備 — 順番を間違えると詰まる

W-8BENは「米国居住者ではない」ことを申告して米国の30%源泉徴収を外すための書類です。日本の個人事業主が出すのは W-8BEN-E ではなく W-8BENで、米国税法上は個人事業主も個人として扱われるためです。郵便番号をハイフン付き（100-0001）で入力する必要があるなど、細かい書式で足止めされやすい箇所でもあります。

無料アプリだけなら有料App契約も銀行口座も不要ですが、アプリ内課金を後から足すなら結局必要になります。

10. 手数料 — 30% / 15%、そして日本のスマホ新法

Small Business Program は前暦年の全アプリ合計収益が100万米ドル以下なら対象で、新規デベロッパも含まれます。申請しないと適用されません。適用開始は「登録が承認された会計月の末日から15日後」なので、登録直後に申し込みます。100万ドルを超えたらその年の残りは30%に戻り、翌年以降に下回れば再び15%の対象になります。

日本では2025年12月18日にスマホソフトウェア競争促進法が全面施行され、アプリ内から外部の決済ページへ誘導できるようになりました。ただし外部決済にもApple側の手数料がかかり、施行4か月後には水準への不満が報じられています。

理解度チェック 2

はじめてアプリを出す個人開発者が、手数料15%の適用を受けるにはどうすればよいですか。

Small Business Program は申請制で、新規デベロッパも対象です。適用は「承認された会計月の末日から15日後」に始まるため、Cのように登録直後に申し込むのが正解です。Aは自動適用されると誤解している点が誤り。Bは売上実績を待つ必要はなく、待つぶん高い手数料の期間が延びるだけです。

11. 提出前に揃える技術要件

プライバシーマニフェストは2024年から必須です。理由の申告が要るAPIを使っていると未対応で弾かれます。サードパーティSDKが持つマニフェストは自動でマージされます。

SDKの必須期限はクラウドMac選びに直結します。借りたMacのXcodeが古いとアップロードで落ちるため、契約前に「Xcodeのバージョンを選べるか、更新されるか」を確認してください。中古Macを買う場合も同じで、Xcode 26 が動くOSまで上げられる機種かが実質的な最低条件になります。

12. TestFlight — Macも実機もない人ほど使う

Mac無し開発で一番効いてくる制約がこれです。クラウドMacにはiPhoneを物理接続できないため、Xcodeから実機を繋いでデバッグという定番の手が使えません。

代わりにTestFlightで自分のiPhoneに配って確認します。ログはXcodeのコンソールで拾えないので、画面にログを出す仕組みをアプリ側に仕込んでおきます。実例でも同じ対処が取られています。

理解度チェック 3

クラウドMacを使っていて、手元のiPhoneで動作を確認したい。最も手早い方法はどれですか。

内部テストは最大100人で審査なし・即配布なので、自分1人が確認する用途には最速です。Aの外部テストは、そのバージョンの最初のビルドで Beta App Review を通す必要があり待ち時間が生まれます。Cはクラウド上のMacに物理的な端末を接続できないため、そもそも成立しません。

13. 審査 — 期間と、リジェクトの三大理由

平均は24時間以内ですが、新規アカウントの初回提出は2〜3日かかることがあります。発売日から逆算するときは初回だけ多めに見ておきます。

4.3は「似ている」だけで飛んできます。実務上の対処は、何が既存と違うのかを審査メモに文章で書いて添えることです。リジェクトはResolution Centerでやり取りしますが、感情的な反論ではなく指摘番号に1つずつ答えます。

⚠️

AIを使ったアプリは2026年時点で4.3の警戒対象です。「AIで作った」ではなく「何が新しいか」を書いてください。

14. Windowsユーザーが実際に詰まる4か所

基本動作はWindows側で確定できることを全部確定させてからMacに繋ぐことです。先ほどの実例では3回連続でリジェクトを受けており、そのたびにクラウドMacへ接続し直すことになります。

加えて、Mac未経験だと Command キーの位置、Finder、キーチェーン、ターミナルといった操作の差そのものにも時間を取られます。ここも接続時間として課金されるという前提で見積もってください。

15. Macに繋ぐ時間を最小化する設計

目標は「Macでやることをアーカイブとアップロードだけにする」ことです。実例ではメタデータの修正を月に1回へまとめる運用にして、接続時間を圧縮しています。

次の段階は自動化です。CIサービスや GitHub Actions の macOSランナーにビルドとTestFlight配信を任せれば、手動でMacに繋ぐ時間をほぼゼロにできます。署名まわりは、証明書とプロファイルを暗号化してプライベートGitに置く fastlane match が定番です。

16. 特許は取れるのか — 「アイデア」は特許にならない

特許法でいう「発明」は自然法則を利用した技術的思想の創作で、単なる思いつきやビジネスのアイデアは含まれません。特許庁の審査基準では、ソフトウェアによる情報処理がハードウェア資源（CPU・メモリなど）を用いて具体的に実現されている場合に限り発明に該当するとされています。

ですから「家計簿を自動で分類するアプリ」は特許になりません。どういう手順で、どのデータを、どう処理して分類を実現するのかまで具体化して、はじめて土俵に乗ります。

💡

「アイデアを盗まれる」という不安に、特許はほとんど答えてくれません。特許が守るのは仕組みであってアイデアではないからです。「特許を取れるか」の前に「そもそも発明があるか」を確認してください。

17. 一番大事な落とし穴 — 公開したら原則アウト

特許はまだ世に出ていないものにしか与えられません。公開してしまうと、自分で公開した場合でも原則として取れなくなります。

日本には救済制度（新規性喪失の例外・特許法30条）があります。ただし公開から1年以内の出願に加えて、出願と同時に申し出て、30日以内に証明書を提出する手続きが要ります。黙っていても適用されません。

そしてApp Storeは世界配信です。日本の例外規定で日本の特許は救えても、欧州は原則グレースピリオドなし、中国も国際展覧会や指定学会など限られた場合のみで、世界で権利化する道は事実上そこで閉じます。

⚠️

特許を検討するなら、判断は「発売日の前」ではなく「テスト配布の前」です。TestFlightの外部テスト（最大10,000人）も公開とみなされうるため、内部テスト（100人・関係者のみ）とはリスクが違います。

理解度チェック 4

アプリを App Store で公開したあとに「この仕組みで特許を取りたい」と思いつきました。正しい理解はどれですか。

Cが正解です。日本の新規性喪失の例外は1年以内の出願に加えて、出願と同時の申し出と30日以内の証明書提出が必要で、Aのように「自由に」出願できるわけではありません。Bは日本国内などでは救済制度が実際に機能するため言い過ぎです。ただしApp Storeは世界配信なので、Cの状態でも取れる国は大きく減ります。

18. 特許・商標・著作権・意匠 — 個人開発者の現実解

権利どう手に入るか何を守るか
著作権書いた瞬間に自動で発生。手続き不要書いたコードそのもの（アイデアは守らない）
商標出願して登録。1区分 約44,900円／10年アプリ名・アイコン
意匠出願して登録。2020年4月からGUI単独で可能に画面デザイン。存続25年
特許出願 → 審査請求 → 登録。出願から3年以内に審査請求具体的な処理の仕組み

個人開発者にとって実害が出やすいのは特許ではなく商標です。アプリ名を他人に先に登録されると改名を迫られます。

「とらない」も戦略です。公開してしまえばそれが先行技術になり、同じものを他人が後から特許化することも難しくなります。1本目のアプリで数十万円と数年を特許に使う合理性は、多くの場合ありません。

🔑

迷ったときの優先順位は ①商標（名前）→ ②著作権（自動なので何もしない）→ ③意匠 → ④特許 です。

19. サンプルスケジュール（3か月）

登録・税務・知財は、アプリの実装と並行して進む作業です。ここを後回しにすると、アプリは完成しているのに出せない期間が生まれます。

特に知財はやり直しが効きません。判断そのものを最初のブロックに置いてください。組織で登録するならD-U-N-S番号の取得が全体のクリティカルパスになります。

理解度チェック 5

3か月でリリースする計画を立てるとき、最初の1か月に必ず入れるべきものはどれですか。

Cが正解です。組織登録はD-U-N-S取得で数週間かかることがあり、特許はテスト配布より前でないと判断そのものが手遅れになります。どちらも後から取り返せません。Aはアーカイブ直前で足り、借りている期間がそのまま費用になります。Bは重要ですが、審査と並行して2か月目に進めても間に合います。

まとめ

作れる。出せないだけ

Windowsで止まるのは署名・アーカイブ・アップロードなど4工程。登録も審査対応もブラウザで完結します。

性能は作るものから逆算

Windowsで書いてMacはビルド専用、という形にできるなら、Macの性能を悩む必要そのものがありません。

PCにmacOSは入れられない

SLAがApple製ハードウェアに限定しています。借りるかCIに投げるかの二択です。

手続きは開発と並走

D-U-N-S・税務・15%の申請は後回しにすると、完成しているのに出せない期間が生まれます。

知財はテスト配布の前に

公開すると特許の道は大きく狭まります。個人開発者の現実解は、まず名前を守る商標です。
